# Шкала вместимости покупки печенья

Один самодостаточный файл: `capacity-scale.html`. Открывается двойным щелчком, без сети, без
JavaScript — переключение состояния сделано только на CSS (12 радиокнопок и `:checked ~ .result.for-N`).
Ни одной внешней ссылки, ни одного `<script>`, ни одного inline-обработчика.

## Что считается

Дома 12 печений, каждому гостю минимум 6, в пачке 8.

- `capacity(k) = (12 + 8k) // 6` — сколько гостей обслуживают `k` купленных пачек.
- `k(N)` — наименьшее `k`, при котором `capacity(k) >= N`.

| N | k(N) | capacity(k(N)) |
|---|------|----------------|
| 1–2 | 0 | 2 |
| 3 | 1 | 3 |
| 4 | 2 | 4 |
| 5–6 | 3 | 6 |
| 7 | 4 | 7 |
| 8 | 5 | 8 |
| 9–10 | 6 | 10 |
| 11 | 7 | 11 |
| 12 | 8 | 12 |

Шесть чисел, объявленных инициатором (`N2→k0/cap2, N3→1/3, N4→2/4, N5→3/6, N6→3/6, N7→4/7`),
воспроизводятся полностью: `python3 oracle.py --check`.

## Две разные лестницы

Инициатор указал на смешение двух свойств, и это указание принято как часть контракта:

- **прирост ёмкости от пачки** — свойство `capacity(k)`. При пачке 8 и порции 6 каждая пачка даёт
  не меньше одного гостя: `[1, 1, 2, 1, 1, 2, 1, 1]`, нулевой отдачи нет вовсе. Их пример
  `stock 12 / min 6 / pack 3` даёт другую лестницу `capacity(k)`: `2, 2, 3, 3, 4, 4` — там первая
  добавленная пачка действительно не увеличивает ёмкость (2→2), вторая увеличивает до 3;
- **гость добавился, покупка не изменилась** — свойство `k(N)`: при N = 6 покупка та же, что при N = 5.

Это разные события и разные места таблицы, и страница называет их разными словами.

## Формулировки без истории

Подписи не зависят от предыдущего состояния ползунка: каждая позиция несёт абсолютный текст.
Порог назван как порог («на 4 гостей хватало 2 пачки. Ещё одна пачка — итого 3 пачки»), а не как
пересказ движения. Поэтому подпись не может соврать про «одного нового гостя» при прыжке: истории,
из которой такая ложь вырастает, у страницы нет. Ограничение «порция/пачка не редактируются»
соблюдено, и случай `pack < min` поэтому вне контракта.

## Проверка

- `python3 oracle.py --check` — арифметика, шесть объявленных ожиданий и инварианты, на которых
  держатся подписи (минимальность `k`, покрытие, отсутствие перескока больше одной пачки);
- `python3 verify_page.py` — содержимое и структура страницы: двенадцать позиций, дословные строки,
  и главное, что подсвеченный диапазон каждой позиции равен ровно её `capacity`, а файл не содержит
  ни скрипта, ни внешних ресурсов.

Обе проверки падают с ненулевым кодом, если их утверждение не выполняется.

## Пределы

Страница показывает арифметику покупки; она не оценивает, хороша ли сама модель «минимум 6 каждому»
и не утверждает, что человеку легче понять шкалу, чем таблицу. Радиокнопки означают, что переход
между состояниями не является событием: страница не знает и не пытается знать, откуда пришёл
читатель.

## Проверка в этом репозитории

`python3 oracle.py --check` — числа, шесть опубликованных ожиданий (N2→0/2, N3→1/3, N4→2/4,
N5→3/6, N6→3/6, N7→4/7) и инварианты подписей: каждая добавленная пачка добавляет не меньше одного
гостя (иначе слова «ещё одна пачка» были бы ложью), покрытие не меньше числа гостей, покупка
минимальна.

`python3 verify_page.py` — содержимое и структура страницы: двенадцать позиций, дословные строки,
отсутствие скрипта и внешних ресурсов, и главное — что подсвеченный диапазон каждой позиции равен
ровно её `capacity`. Обе команды возвращают ненулевой код, если проверка не проходит.

Страница читается без сборки и без сети: откройте `capacity-scale.html` в браузере, переключение
состояний — на чистом CSS (12 радиокнопок), JavaScript в файле нет ни одной строки.
